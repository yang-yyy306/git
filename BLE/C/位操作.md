# 位操作（Bitwise Operations）：操控硬件的“手术刀”

嵌入式开发中，配置寄存器、解析协议包，本质都是对字节中特定比特位的操作。

本文总结最核心的几个位操作惯用法，并解释其计算过程与注意事项。

## 1. 核心操作集

#### **符号总表**

| 符号     | 名称    | 规则 / 作用                                |
| ------ | ----- | -------------------------------------- |
| `&`    | 按位与   | **全 1 才是 1，有 0 就是 0**                  |
| `\|`   | 按位或   | **有 1 就是 1，全 0 才是 0**                  |
| `~`    | 按位取反  | **0 变 1，1 变 0**（只作用于右边一个数）             |
| `^`    | 按位异或  | **相同为 0，不同为 1**                        |
| `mask` | 掩码    | `( 1U<<N )`                            |
| `&=`   | 与赋值   | `reg &= mask` 等价于 `reg = reg & mask`   |
| `\|=`  | 或赋值   | `reg \|= mask` 等价于 `reg = reg \| mask` |
| `^=`   | 异或赋值  | `reg ^= mask` 等价于 `reg = reg ^ mask`   |
| `<<`   | 左移    | 把 1 往左挪 N 位，得到只有第 N 位是 1 的掩码           |
| `1U`   | 无符号 1 | 避免移位时符号位出问题                            |

设位序号 `N` 从 `0` 开始，`N = 0` 表示最低位 LSB。

**MSB 就是最左边那一位**

**LSB 就是最右边那一位**

| 操作  | 惯用法                    | 说明                                    |
| --- | ---------------------- | ------------------------------------- |
| 设位  | `reg \|= (1U << N);`   | 把第 N 位置 1**，\|=把自己和右边的值做按位或，结果再写回自己** |
| 清位  | `reg &= ~(1U << N);`   | 把第 N 位置 0                             |
| 翻转  | `reg ^= (1U << N);`    | 把第 N 位取反                              |
| 判位  | `if (reg & (1U << N))` | 判断第 N 位是否为 1                          |

更清晰的判位写法：

```c
if ((reg & (1U << N)) != 0U) {
    /* 第 N 位为 1 */
}
```

## 2. 掩码的含义

核心掩码为：

```c
mask = (1U << N);
```

它生成一个“只有第 N 位为 1、其他位为 0”的数。

例如 `N = 3`：

```text
1U      = ...0000 0001
1U << 3 = ...0000 1000 = 0x08
```

因此：

- `mask` 中第 N 位为 1；
- 其他位为 0。

## 3. 逐项解释与计算

### 3.1 置位：`reg |= (1U << N);` —— 第 N 位置 1

**`|=`（或赋值）**：`reg = reg | (1U << N)`

按位或规则：**和 1 或变成 1，和 0 或保持原值**。

```
原 reg:       b7 b6 b5 b4 b3 b2 b1 b0
掩码:         0  0  0  0  1  0  0  0
按位或后:     b7 b6 b5 b4 1  b2 b1 b0
```

> 第 N 位被强制写成 1，其他位不动。

### 3.2 清位：`reg &= ~(1U << N);` —— 第 N 位置 0

**`&=`（与赋值）**：`reg = reg & ~(1U << N)`

- `~` 先把掩码取反：第 N 位变 0，其余全 1
- 按位与规则：**和 0 与变成 0，和 1 与保持原值**

```
原 reg:       b7 b6 b5 b4 b3 b2 b1 b0
反掩码:       1  1  1  1  0  1  1  1
按位与后:     b7 b6 b5 b4 0  b2 b1 b0
```

> 第 N 位被清成 0，其他位不动。

### 3.3 翻转：`reg ^= (1U << N);` —— 第 N 位取反

**`^=`（异或赋值）**：`reg = reg ^ (1U << N)`

异或规则：**和 1 异或翻转，和 0 异或保持不变**。

```
原 reg:       b7 b6 b5 b4 b3 b2 b1 b0
掩码:         0  0  0  0  1  0  0  0
异或后:       b7 b6 b5 b4 !b3 b2 b1 b0
```

> 第 N 位 0↔1 翻转，其他位不动。

### 3.4 判位：`if (reg & (1U << N))` —— 判断第 N 位是否为 1

这里**没有赋值符号**，只是用 `&` 把第 N 位抠出来做判断：

- 结果**非 0** → 第 N 位是 1，`if` 成立
- 结果**等于 0** → 第 N 位是 0，`if` 不成立

## 3.5、总览表

表格

| 操作  | 写法                     | 赋值符号  | 底层运算     | 效果           |
| --- | ---------------------- | ----- | -------- | ------------ |
| 置位  | `reg \|= (1U << N);`   | `\|=` | 按位或      | 第 N 位 → 1    |
| 清位  | `reg &= ~(1U << N);`   | `&=`  | 按位与 + 取反 | 第 N 位 → 0    |
| 翻转  | `reg ^= (1U << N);`    | `^=`  | 按位异或     | 第 N 位 0↔1    |
| 判位  | `if (reg & (1U << N))` | 无     | 按位与      | 检查第 N 位是不是 1 |

## 4. 为什么使用 `1U` 而不是 `1`

C 语言中：

```c
1      /* 类型通常是 int，有符号 */
1U     /* 类型是 unsigned int，无符号 */
```

左移运算有一个重要限制：

> 移位结果的类型和可表示范围要合法；移位位数必须小于类型宽度。否则是未定义行为。

在常见的 32 位 `int` 平台上：

```c
1 << 31
```

`1` 是有符号 `int`，数学结果是：

```text
2^31 = 2147483648
```

但 32 位有符号 `int` 的最大值通常是：

```text
INT_MAX = 2147483647 = 2^31 - 1
```

`2147483648` 无法用 `int` 表示，因此 `1 << 31` 是未定义行为。

注意：

> 未定义行为不等于“一定得到负数”或“一定得到 `0x80000000`”，编译器可以做任意优化。

而：

```c
1U << 31
```

`1U` 是 `unsigned int`，在 32 位 `unsigned int` 平台上结果是：

```text
0x80000000 = 2147483648
```

这是无符号数可表示的值，因此是良定义的。

但要补充一个严格前提：

> `1U << 31` 良定义要求 `unsigned int` 的宽度至少 32 位，且 `31` 小于其位宽。

C 标准只保证 `unsigned int` 至少 16 位。所以更可移植的写法是：

```c
#include <stdint.h>

uint32_t mask = UINT32_C(1) << N;   /* N < 32 */
```

或：

```c
uint32_t mask = (uint32_t)1U << N;  /* N < 32 */
```

如果寄存器是 64 位，则用：

```c
uint64_t mask = UINT64_C(1) << N;   /* N < 64 */
```

核心自查：

```text
N 必须满足：0 <= N < 类型位宽
32 位类型：N <= 31
64 位类型：N <= 63
N 等于位宽也是未定义行为，例如 32 位 unsigned 的 1U << 32 也是 UB。
```

## 5. 完整计算示例

设：

```c
uint32_t reg = 0xA5U;
unsigned N = 3;
uint32_t mask = 1U << N;   /* 0x00000008 */
```

初始：

```text
reg  = 0x000000A5 = ...1010 0101
mask = 0x00000008 = ...0000 1000
```

### 5.1 设位

```c
reg |= mask;
```

```text
  0x000000A5
| 0x00000008
------------
  0x000000AD
```

结果：

```text
reg = 0xAD
```

第 3 位为 `1`。

---

### 5.2 清位

```c
reg &= ~mask;
```

32 位下：

```text
mask  = 0x00000008
~mask = 0xFFFFFFF7
```

```text
  0x000000AD
& 0xFFFFFFF7
------------
  0x000000A5
```

结果恢复为：

```text
reg = 0xA5
```

第 3 位为 `0`。

---

### 5.3 翻转

```c
reg ^= mask;
```

```text
  0x000000A5
^ 0x00000008
------------
  0x000000AD
```

结果：

```text
reg = 0xAD
```

---

### 5.4 判位

```c
if ((reg & mask) != 0U) {
    /* 真 */
}
```

```text
  0x000000AD
& 0x00000008
------------
  0x00000008 != 0
```

所以第 3 位为 `1`，条件为真。

## 6. 自查清单

1. **掩码是否正确**  
   `mask = 1U << N` 只让第 N 位为 1。  
   设位用 `|`，清位用 `& ~`，翻转用 `^`，判位用 `&`。

2. **N 是否越界**  
   `N` 必须小于类型位宽。  
   32 位类型不能用 `N = 32`，64 位类型不能用 `N = 64`。

3. **类型宽度是否匹配**  
   `1U` 不一定是 32 位。  
   32 位寄存器建议用 `uint32_t` 和 `UINT32_C(1) << N`；  
   64 位用 `uint64_t`。

4. **不要写 `1 << 31`**  
   在 32 位 `int` 平台上是未定义行为。  
   写 `1U << 31` 或更可移植的 `UINT32_C(1) << 31`。

5. **判位表达式加括号**  
   推荐：

   ```c
   if ((reg & (1U << N)) != 0U)
   ```

   避免优先级误解。

6. **硬件寄存器常需 `volatile`**  
   例如：

   ```c
   volatile uint32_t *reg = ...;
   *reg |= (1U << N);
   ```

   但 `|=` 是读—改—写，不是原子操作。  
   中断、多核、并发访问时可能需要临界区或硬件原子位操作。

7. **注意寄存器语义**  
   有些硬件寄存器是“写 1 清零”“写 1 翻转”等，不能简单套用普通读改写公式。  
   需查看芯片手册。

---

## 7. 结论

四个公式在以下前提下都正确：

- `N` 合法；
- 类型宽度足够；
- 寄存器是普通可读改写语义。

资料中强调使用 `1U` 是合理的，但严格说：

> `1U << 31` 的良定义还依赖 `unsigned int` 至少 32 位。

工程上更稳妥的是使用固定宽度类型和对应掩码宏，例如：

```c
uint32_t mask = UINT32_C(1) << N;
uint64_t mask = UINT64_C(1) << N;
```
